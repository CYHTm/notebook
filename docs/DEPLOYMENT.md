# Публикация на GitHub Pages

Проект — статический сайт. Для него не нужны VPS, backend, база данных, API-ключи или пользовательские секреты в GitHub Actions.

Ожидаемый стандартный адрес для этого репозитория: **https://cyhtm.github.io/notebook/**. Адрес становится рабочим только после включения Pages и успешного задания `Deploy to GitHub Pages`; точную ссылку возвращает это задание. При настроенном собственном домене адрес будет другим.

## Однократная настройка владельцем

1. Откройте [Settings → Pages](https://github.com/CYHTm/notebook/settings/pages).
2. В **Build and deployment → Source** выберите **GitHub Actions**, не `Deploy from a branch`.
3. Если есть защита окружения `github-pages`, в **Settings → Environments → github-pages → Deployment branches and tags** разрешите ветку **`arena/01a07527-notebook`**. Существующие ограничения и подтверждения удалять не нужно. Для будущей публикации из `main` разрешите и её.
4. Откройте [Actions](https://github.com/CYHTm/notebook/actions) и workflow **Publish XBOOK LAB**. Если его первый запуск произошёл до включения Pages и завершился ошибкой публикации, выберите **Re-run all jobs**.
5. Дождитесь зелёного `Deploy to GitHub Pages`. Ссылка появится в задании и в Settings → Pages. Публикация может занять несколько минут.

Текущая рабочая ветка — `arena/01a07527-notebook`. Создавать `gh-pages` или коммитить `dist/` не требуется. `main` не изменяется во время настройки этой сессии; публикация из неё начнёт работать после обычного переноса workflow и исходников в неё владельцем.

### Приватность и тариф

GitHub Pages доступен для публичных репозиториев на GitHub Free. Для приватного репозитория нужен подходящий тариф, например GitHub Pro для личного аккаунта. Если раздел Pages предлагает сменить тариф или видимость, это отдельное решение владельца: **workflow не меняет приватность репозитория и не оформляет подписку**.

Опубликованный Pages-сайт обычно общедоступен, даже когда исходный репозиторий приватный. Не добавляйте ключи, личные файлы и секреты в `public/` или в клиентский код.

Если API отвечает `Resource not accessible by integration` при чтении/изменении Pages, это ограничение прав интеграции. Владелец может выполнить настройку выше непосредственно в GitHub. Передавать токены или пароли в чат не нужно.

Официальные требования: [GitHub Docs — создание Pages-сайта](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Что делает workflow

Файл: `.github/workflows/pages.yml`.

При push в `arena/01a07527-notebook` или `main`:

1. Устанавливает Node.js 22 и зависимости строго из lockfile (`npm ci`).
2. Проверяет форматирование, TypeScript и модульные тесты.
3. Собирает production и браузером проверяет её размещение в `/notebook/`: картинку, favicon, стили, все маршруты, перезагрузку и диалоги.
4. Загружает **только `dist/`** как Pages-артефакт.
5. Публикует проверенный артефакт через официальный `actions/deploy-pages`.

Официальные actions закреплены по SHA. Задание сборки получает только `contents: read`; публикация — `pages: write` и `id-token: write`. Используется стандартный временный токен GitHub Actions, без ручного создания секретов.

`workflow_dispatch` оставлен для будущего ручного запуска. GitHub показывает кнопку такого запуска после появления workflow в default branch. Пока файл находится только в рабочей ветке, используйте push в неё или повтор существующего запуска, а не рассчитывайте на эту кнопку.

## Пути и маршрутизация

В Vite задано `base: "./"`. Иллюстрация и favicon используют `BASE_URL`. Поэтому сайт работает как в корне предпросмотра, так и в папке репозитория `/notebook/` или на собственном домене.

Навигация использует hash: `/notebook/#/journal`. Перезагрузка не требует серверного rewrite и отдельного `404.html`.

Проверить такой вариант локально:

```sh
npm ci
npm run test:pages
```

Для ручного просмотра сборки в той же папке:

```sh
npm run build
npm run preview -- --base /notebook/
```

Откройте `http://localhost:4173/notebook/` на компьютере, где запущен сервер. В удалённом предпросмотре используйте внешний preview-адрес с тем же путём `/notebook/`.

## Личные данные после смены адреса

`localStorage` привязан к origin браузера. Записи из Arena Preview **не переносятся автоматически** на `cyhtm.github.io`. Перед переходом скачайте текстовый отчёт, если уже внесли данные. В v1 это читаемая копия, не файл автоматического импорта.

В Git и Pages-артефакт не попадают браузерные записи пользователя, `.cache/`, `node_modules/`, тестовые скриншоты и локальные отчёты.
