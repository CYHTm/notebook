# XBOOK LAB

Русскоязычный справочник и личный помощник по осмысленной настройке **Infinix XBOOK B15 BL51A7H / 71005000295 / Ryzen 5 7535HS**. Приоритет — игры с приемлемыми нагревом и шумом, с учётом подставки **DeepCool MULTI CORE X6**.

Это **независимый проект**, не приложение Infinix, AMD или Microsoft. Справочная редакция зафиксирована на **06.09.2026**. Версии программ, известные проблемы и условия поддержки не обновляются автоматически.

## Что работает

- Восемь разделов: обзор и паспорт, аудит после твикеров, Windows и драйверы, игровые профили, охлаждение, Process Lasso, журнал замеров, источники.
- 17 пошаговых инструкций: действия, проверка результата, ограничения и возврат назад. Восемь отмечаемых шагов личного маршрута.
- Поиск по разделам, текстам инструкций **и командам**: `Ctrl/Cmd + K` или `/` вне полей ввода; стрелки, `Enter`, `Escape`.
- Паспорт с полезным состоянием «Пока не знаю». Никаких предполагаемых сборок Windows, BIOS или температур.
- Планы «Тихая игра», «Баланс», «Приоритет FPS» и целевой FPS-лимит. Черновик отделён от сохранённого плана.
- Схема четырёх режимов X6. Она меняет только иллюстрацию и предлагаемые условия теста.
- Ручные замеры: создание, проверка значений, редактирование, подтверждаемое удаление, сравнение двух записей. Учитываются FPS, 1% low, максимальные температуры и субъективный шум. При разных или неполных условиях выводится предупреждение.
- Текстовый отчёт с паспортом, планом, отметками, замерами и источниками. При повреждённом хранилище можно отдельно скачать его исходную запись.
- Адаптивная вёрстка, клавиатурная навигация, нативные диалоги с удержанием/возвратом фокуса, поддержка reduced motion.

**Сайт не читает датчики, не выполняет команды, не управляет Windows, BIOS, Process Lasso или вентиляторами.** Значения FPS в профилях — цели ограничителя, не обещание производительности. Предустановленных «результатов» нет.

## Запуск

Требуется **Node.js 22.12+** и npm. Проверено на Node 22.22.3 / npm 10.9.8.

```sh
npm ci
npm run dev
```

Сервер разработки слушает `0.0.0.0:5173`. Для Arena разрешён домен `.e2b.app`; браузерный код не обращается к `localhost` как к стороннему API.

```sh
npm run build
npm run preview
```

Production preview: порт `4173`. Для размещения нужен только статический HTTPS-хостинг с содержимым `dist/`. Маршруты используют hash (`#/journal`), поэтому серверный роутер и rewrite для внутренних страниц не нужны. Открывать исходный `index.html` через `file://` не следует.

## GitHub Pages

Автопубликация подготовлена в `.github/workflows/pages.yml`: проверка → production-сборка → браузерный тест пути `/notebook/` → Pages-артефакт → публикация. Генерируемый `dist/` в Git не добавляется.

Владельцу нужно один раз выбрать **Settings → Pages → Source → GitHub Actions** и разрешить рабочую ветку в окружении `github-pages`, если действуют ограничения. Для приватного репозитория нужен тариф с поддержкой Pages. Приватность автоматически не меняется.

Настройка, требования и перенос локальных данных: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

```sh
npm run test:pages
```

Эта команда собирает production и проверяет её под префиксом `/notebook/`, включая пути изображений, favicon и перезагрузку внутренних страниц.

## Стек

React 19, TypeScript 7, Vite 8, Tailwind CSS 4 с Vite-плагином, Motion for React, Lucide. Шрифты Golos Text, Manrope и IBM Plex Mono поставляются локально через Fontsource. Точные версии зафиксированы в `package.json` и `package-lock.json`.

Никакого backend, регистрации, аналитики, сторонних виджетов или удалённых шрифтов. Внешние страницы открываются только по ссылкам пользователя.

## Данные и ограничения

- Ключ `localStorage`: **`xbook-lab:v1`**, схема `1`; максимум **200 замеров**.
- Состояние проверяется при чтении. Повреждённые, неизвестные или частично некорректные данные **не перезаписываются автоматически**. Для возобновления сохранения нужен подтверждённый сброс; перед ним доступны отчёты.
- При запрете хранения или исчерпании квоты изменения остаются только в памяти текущей страницы. Интерфейс предупреждает об этом и не обозначает план как сохранённый в браузере.
- Подтверждаемый сброс затрагивает только ключ этого сайта, не чужие данные браузера и не настройки ноутбука.
- Данные не синхронизируются между устройствами, браузерами, origin и открытыми вкладками. Для работы с журналом лучше использовать одну вкладку. Очистка данных сайта удалит локальный прогресс. Экспортируйте отчёт заранее.
- В v1 нет импорта отчёта, автоматической телеметрии и гарантированного offline-режима. TXT — читаемая копия, не формат автоматического восстановления.
- Не вводите серийные номера, пароли или ключи BitLocker. Сайт их не запрашивает.

## Проверки

```sh
npm run typecheck
npm test
npm run test:e2e
npm run format:check
npm run build
```

**50 модульных тестов** проверяют данные, валидацию, сравнение, отчёт, маршруты и целостность ссылок. **23 браузерных теста** проверяют пользовательские сценарии и доступность через axe. Подробности и границы проверки: [docs/QA.md](docs/QA.md).

### Браузер для Playwright

Обычный вариант:

```sh
npx playwright install chromium
npm run test:e2e
```

В Linux-сandbox, где CDN браузера недоступен, конфигурация использует npm-пакет `@sparticuz/chromium`. Исполняемый файл извлекается во временный каталог, дополнительные NSS-библиотеки — в игнорируемый `.cache/browser-libs`. Никакие браузерные бинарники не входят в Git или production-сборку.

Скриншоты и отчёты тестов находятся в `.cache/`. Vite не следит за этой папкой: HTML из трассировок не должен вызывать перезагрузку приложения. Трассировка настроена на первый повтор теста, а не на каждый шаг обычного запуска.

## Структура

```text
src/
  App.tsx                состояние, сохранение, навигация, оболочка
  components/            диалоги, формы, справочные элементы, схема X6
  data/                  инструкции, 21 источник, паспорт модели
  lib/                   типы, валидация, сравнение, отчёт, маршруты
  pages/                 восемь разделов
  styles.css             редакционная сетка, адаптивность, доступность
public/                  favicon и оптимизированная иллюстрация
tests/                  Playwright, axe, настройка Linux-браузера
docs/                   исследование и результаты проверки
```

Обновляя справочник, сначала перепроверьте первоисточники, затем одновременно обновите текст, дату редакции и исследовательскую заметку. Не заменяйте дату динамическим «сегодня»: это создало бы ложное впечатление свежести.
